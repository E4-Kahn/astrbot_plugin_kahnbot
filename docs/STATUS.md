# 结档说明（2026-11-12）

**状态：已封存。** 代码停在 tag `v0.4.1`，不再维护。

## 这是什么

一个装在 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 上的群聊陪伴插件。主人私聊她、
或在四五个人的小群里叫她的名字 / @ 她 / 拍一拍，她会回话；平时不吭声，但把看到的话记在心里。
不做公开群，不做多租户。

## 做到了哪一步

八个里程碑全部落地，`v0.4.1` 是最后一个可用版本：

| 里程碑 | 内容 |
|---|---|
| M1 | 数据层：SQLite 流水（`message` / `fact_index` / `wake_quota` / `meta`），catch-all 记录每条消息，`/kahn` 指令组 |
| M2 | 唤醒与配额：@ / 拍一拍 / 名字三种唤醒，2 秒防抖窗口（可配、5 秒硬上限），每日唤醒配额，陌生人私聊屏蔽 |
| M3 | 情绪层：九维情绪 + blame + 五档（日常 / 委屈 / 生气 / 害怕 / 回避），心跳漂移，`/kahn mood` |
| M4 | 检索与注入：bge-m3 向量 + 字面混合排序，隐私层过滤，`on_llm_request` 注入 `<memory>` |
| M5 | 长期记忆：「记住…」识别、LLM 重要度打分、见闻层（`owner` / `observed` / 流水）、六小时汇总、已被取代、30 天归档、到点提醒（cron basic job） |
| M6 | 主动说话与回避档：冷却 6 小时、日限 2 条、深夜免打扰；生气到阈值会躲起来，被哄 / 被连拍 / 主人一直找才出来，被吞的话下次开口还记得 |
| M7 | 情绪与上下文进对话：每轮带当前心情、最近几句群聊、按需检索的记忆 |
| M8 | 分段发送：回复拆成 1~3 条，按字数估打字间隔，私聊显示「正在输入」 |

细节在 [`IMPLEMENTATION.md`](IMPLEMENTATION.md)（§2 里程碑、§7 交接、§8 未排期方案）。

## 为什么封存

经过一段时间真机测试，整体效果不理想，决定暂停开发并封存。

（具体的"哪里不理想"没有展开记录。如果以后要重开，第一步应该是把这句话还原成可复现的
现象——是检索给错记忆、说话不像人、主动说话太烦、还是又慢又贵——否则改了也不知道有没有变好。）

## 封存时的已知问题

这些是开发过程中就知道、但没解决的：

- **检索阈值靠标定**：bge-m3 下无关语句余弦约 0.48、相关语句约 0.87，`recall_min_score` 定在
  0.35。换 embedding 模型就得重新标定，否则要么全不召回、要么全召回。
- **重要度靠模型自评**：写入时让 LLM 给 0–100 分，同一句话问两次可能给不同分数，排序会抖。
- **群聊里的转述**：群友说的话进 `observed` 层，永不触发提醒（`owner` 层才提醒），但注入时仍可能
  被当成事实参考——只是标了"未必属实"。
- **成本**：单轮对话约 3–3.8k token；每 6 小时一次汇总；「记住…」时多一次打分调用。
- **数据与目录名绑定**：数据在 `data/plugin_data/astrbot_plugin_kahnbot/`，改插件目录名 = 丢数据。
- **cron basic job 不持久化**：重启后必须由插件自己按 `due_ts` 重新挂 handler，否则提醒丢。
- 其余（SQLite 并发、拍一拍没昵称、主动消息要手动回写历史等）见 `IMPLEMENTATION.md` §5。

## 封存时做了什么

- 打 tag `v0.4.1`，仓库与运行环境解绑。
- 运行环境（AstrBot、SnowLuma）已卸载；运行数据（流水、情绪状态、记忆文件）未保留，仓库里也没有。
- 仓库清理过一遍：不含 QQ 号、token、API Key、邮箱等个人信息。

## 如果要重开

1. **环境**：Python 3.12 + `uv tool install astrbot`（4.29.4 实测），
   [SnowLuma](https://github.com/SnowLuma/SnowLuma) 作为 OneBot v11 端；完整步骤在 [`DEPLOYMENT.md`](DEPLOYMENT.md)。
2. **装插件**：仓库放进 `AstrBot/data/plugins/`，或用目录联接链过去（改代码后要重启，`--reload` 不会热更）。
3. **跑测试**：`python tests/smoke_m1.py` … `smoke_m8.py`，全部离线、不调模型。
4. **数据**：从零开始——`/kahn reset confirm` 或直接删 `data/plugin_data/astrbot_plugin_kahnbot/`。
5. **没做的**：`IMPLEMENTATION.md` §8 列的五个方向（检索优化、`[沉默]` 标记、人物小档案、
   表情包、空间日记）都没排期。
6. **先读哪本**：`REQUIREMENTS.md`（要什么、不要什么）→ `IMPLEMENTATION.md` §7（坑）→
   `refs/`（四份参考插件笔记与设计稿）。
