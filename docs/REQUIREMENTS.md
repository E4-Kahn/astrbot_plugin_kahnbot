> 状态：功能需求**已确认**（F1、F3~F24；F2 为占位）；Q8 已定三层判定、Q12 已定；实现按 M1~M8 推进，**M1~M8 全部落地**（v0.4.1；0.3.1 / 0.3.2 / 0.4.1 为真机测试后的修复批次）。

这份文档是 KahnBot 的单一事实来源：先在这里把需求聊清楚，再动代码。
每确定一条需求，就补一行到「功能需求」，并把状态从 `待定` 改成 `已确认`。

## 1. 背景与目标

- 背景：AstrBot 默认的对话助手是"无状态应答"——不给上下文就想不起来，不会主动开口，也没有脾气。
  KahnBot 要补的是这一层：**一个会记住、会有情绪起伏、会在合适的时候自己说话的群聊陪伴 bot**。
- 目标：一个有心跳和记忆等功能的群聊陪伴 bot。心跳在后台驱动情绪漂移与记忆老化，记忆负责长期事实的
  写入/检索/隐私隔离，情绪决定她此刻愿不愿意说话、说什么样的语气。（本阶段仍在逐个讨论和补充功能，
  这份目标只定大方向，不锁死细节。）
- 使用范围（2026-11-12 用户确认）：**单实例、单一主人**；只跑在主人的私聊和一个 4~5 人的小群里。
  不面向公开群、不做多租户、不为大规模并发做优化——这条是后面所有"够不够用"判断的前提，
  也意味着：汇总不必设内容边界、陌生人场景基本不会出现（但 F24 仍保留作兜底）。
- 不做什么：
  - 不做"梗百科"这类独立子系统（内置词库、群黑话增删指令、查梗工具都不做）。梗通过记忆系统自然习得——
    主人讲过一遍就是一条事实，没听过就问，不需要她先分辨"这是黑话还是记忆"。见 Q15。
  - 不发布到 AstrBot 插件市场（Q2），不追求市场兼容与上架材料。
  - 不引入"群友影响情绪"的模型（Q7），群友的话只进流水。
  - 不在插件里打包重量级依赖（torch / sentence-transformers），向量复用 AstrBot 的 Embedding Provider。

## 2. 名词约定

| 名词 | 含义 |
| --- | --- |
| 会话 | AstrBot 的 unified_msg_origin，形如 `platform:MessageType:session_id` |
| 主人 | 唯一被记住的用户；本插件只服务一个人 |
| 记忆条目 | 一条可检索的长期事实，含正文、时间、来源、说话人 |
| 流水 | 逐条原始消息记录（谁、何时、在哪个会话、说了什么） |
| 指令 | 以 `/` 开头的消息，由 `@filter.command` 处理 |
| 情绪状态 | 九维数值 + 档位（日常/委屈/生气/害怕/回避），存 `state.json`，不调 LLM |
| 心跳 | 唯一的定时器：驱动情绪漂移、记忆老化、汇总与主动说话 |
| 事实分层 | `owner`（主人亲口）/ `observed`（群友转述）/ `raw`（流水）三层，可信度不同 |
| 插件 | AstrBot 的 Star 包，标识符 `astrbot_plugin_kahnbot` |

## 3. 使用场景

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| S1 | 主人在群里说"记住，我下周三要去杭州" | 写入一条记忆，标注来源为群、说话人为主人 |
| S2 | 主人在群里问"我下周有啥安排" | 检索到该条目并回答，不暴露私聊内容 |
| S3 | 群友在群里闲聊 | 记入流水，可被检索，但回答时明确区分是谁说的 |
| S4 | 群里有人没 @ 她，只喊"鱼宝在吗" | 按关键词唤醒并回复（F10）；若配额用尽则静默，但消息仍进流水（F12） |
| S5 | 主人连续两天没说话，第三天回来 | 情绪处于委屈档，语气随之变化；`/kahn mood` 能看到原因（F17/F19/F22） |
| S6 | 主人说过"下周三体检" | 周三当天他心跳到点，主动提醒一句；群友说"明天是管理员生日"则不会（F16/F21） |

## 5. 非功能需求

- 性能：单条消息处理不额外阻塞事件管线，需要等待的操作放到后台任务。
- 稳定性：外部依赖（LLM、网络、数据库）失败时降级，不抛异常打断对话。
- 数据：用户数据存放于 `data/plugin_data/astrbot_plugin_kahnbot/`，可备份、可迁移。
- 隐私：日志默认不记录完整聊天原文，敏感字段脱敏；私聊条目默认只在「主人语境」里可检索——
  非主人的群聊上下文查不到，主人自己在群里问能带出来（按人判定，不按会话；2026-11-12 定，
  交给主人自己判断该不该当着群里问）。
- 兼容：AstrBot `>= 4.29.4`（本插件只在 4.29.4 上实测过；见 refs/astrbot-capabilities.md 第 11 节），Python `>= 3.12`。
- 依赖：**不新增重量级依赖**。向量检索复用 AstrBot 已配置的 Embedding Provider，不在插件内打包 torch / sentence-transformers。
- 成本：不对每条消息调用 LLM。记录是纯本地写入；LLM 只在被唤醒（@ / 拍一拍 / 关键词）时调用。
- 工作区洁净（2026-11-12 定）：测试与调试只允许在明确的临时目录（如仓库内 `.smoke_tmp/` 或系统临时目录）产生文件，
  **不得在仓库根或 `D:\workspace` 根留下 `data/`、`*.log`、`*.db`、脚本副本**；每次验证结束前清理，收尾时用
  `git status` 与目录列表自查。原因：M3 调试时在 `D:\workspace` 根留下了 `data/`（AstrBot 根被当成当前目录）和两个日志；
  M4 调试又把 `astrbot run` 的输出 tee 成了 `D:\workspace\_m4_run.log`。跑服务的日志一律写 `$env:TEMP`。
